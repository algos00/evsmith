# EVSmith

Tell EVSmith what your Pokémon must **survive**, **KO** and **outspeed**, and it builds the 66-point Stat Point spread that does it with the fewest points. For Pokémon Champions (level 50, doubles, VGC).

The app is a single HTML file with no server and no tracking: open `EVSmith.html` in a browser.

## Use it

- Online: if the maintainer enabled GitHub Pages, the latest release is published there (see the repository's *About* link).
- Offline: download `EVSmith-vX.Y.Z.html` from the [latest release](../../releases/latest) and open it.

A usage guide is built into the page ("How to use EVSmith").

## What it does

- Survive / KO / Speed goals with priorities; weather, terrain, screens, Tailwind, Helping Hand and more per goal.
- Tries every nature, or the one you choose; fixes the points you want fixed.
- For KO goals, shows the minimum points **with and without Helping Hand**.
- Explains which goal needs each point, and can spend leftover points for the best resistance or to tune the HP stat (Leftovers, Sitrus Berry, Life Orb, Substitute, poison…).
- Optional tournament meta (usage and sets from online Limitless tournaments).
- Pokémon pictures (sprites and official artwork from [PokéAPI](https://github.com/PokeAPI/sprites)), a hexagon chart of the spread, a type-coloured theme for light and dark mode.
- Share a setup as a link; export a set for Pokémon Showdown.

## How it is checked

The damage engine is compared with [`@smogon/calc`](https://github.com/smogon/damage-calc) on random cases, and the optimizer with an exhaustive search. See [`tests/README.md`](tests/README.md). Results are still estimates for planning: always test a spread in battle.

## Develop

Requires Node.js 20 or newer.

```
npm ci --prefix tests     # test dependencies (once)
npm run build             # writes dist/EVSmith.html
npm test                  # build + all checks (about a minute)
npm run update-meta       # refresh src/tdata.js from MunchStats (about 11 minutes)
npm run update-sprites    # refresh src/sprites.js (name -> PokéAPI sprite id; one request)
```

Edit the files in `src/`, never `dist/`:

| file | what it is |
|---|---|
| `src/template.html` | page structure and texts (guide, disclaimer) |
| `src/style.css` | styles (mobile first, two columns from 1000px) |
| `src/engine.js` | damage engine |
| `src/ui.js` | optimizer and interface |
| `src/data.js` | game data generated from Pokémon Showdown (do not edit) |
| `src/tdata.js` | tournament data generated by `npm run update-meta` (do not edit) |
| `src/sprites.js` | Pokémon name → PokéAPI sprite id, generated by `npm run update-sprites` (do not edit) |
| `src/shim.js` | localStorage fallback |

## Release

1. Change `version` in `package.json` and commit.
2. Tag it with the same number and push: `git tag v1.1.0 && git push origin v1.1.0`.
3. The *Release* workflow runs the tests, builds the app, creates a GitHub Release with the HTML file attached, and (optionally) publishes it to GitHub Pages. It refuses to run if the tag and `package.json` disagree.

The Pages step is optional and off by default. Without it you still get the Release with the HTML file, which works when opened locally (no server or domain needed). To publish on GitHub Pages (free `<user>.github.io/<repo>/` address, no custom domain needed): *Settings → Pages → Source: GitHub Actions*, then add the repository variable `PUBLISH_PAGES` = `true` (*Settings → Secrets and variables → Actions → Variables*).
